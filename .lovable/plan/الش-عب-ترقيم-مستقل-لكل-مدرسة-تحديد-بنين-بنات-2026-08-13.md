# الشُعب: ترقيم مستقل لكل مدرسة + تحديد بنين/بنات

## الوضع الحالي
- جدول الشُعب فيه قيد فريد على (الصف، رقم الشعبة) على مستوى النظام بالكامل، وليس لكل مدرسة. لذلك إذا أنشأت مدرسة الشعبة 1 للصف الأول، لا تستطيع مدرسة أخرى إنشاء نفس الرقم.
- لا يوجد أي حقل يحدد إن كانت الشعبة للبنين أو للبنات.
- إضافة الشعبة تتم يدويًا بإدخال الرقم، بدون ترقيم تلقائي.

## المطلوب تنفيذه
1. فصل الشُعب بين المدارس: كل مدرسة لها ترقيمها الخاص، ويمكن أن يتكرر نفس رقم الشعبة في مدارس مختلفة.
2. إضافة نوع الشعبة (بنين / بنات) لكل شعبة، مع إظهاره في القوائم والتقارير.
3. الترقيم يبدأ من 1 تلقائيًا لكل صف داخل المدرسة: عند الإضافة يُقترح الرقم التالي المتاح تلقائيًا.

## واجهة المستخدم
- تبويب «الشُعب» في الإعدادات: قائمة اختيار الصف، ثم رقم الشعبة معبأ تلقائيًا بالرقم التالي، مع خيار «بنين / بنات» إلزامي قبل الإضافة.
- جدول الشُعب: عمود جديد «النوع» يظهر بنين أو بنات مع وسم ملوّن.
- أي مكان يظهر اسم الشعبة (الطلاب، الحضور، العلامات، الوظائف، الحصاد العلمي، التقارير) يعرض «الصف س - الشعبة ص (بنين/بنات)».
- شاشة روابط واتساب للشُعب تعرض النوع أيضًا.

## التفاصيل التقنية
- ترحيل قاعدة البيانات:
  - `ALTER TABLE public.sections DROP CONSTRAINT sections_grade_id_section_number_key;`
  - `ALTER TABLE public.sections ADD CONSTRAINT sections_school_grade_number_key UNIQUE (school_id, grade_id, section_number);`
  - إضافة نوع `section_gender` (`boys`, `girls`) وعمود `gender section_gender NOT NULL DEFAULT 'boys'` على `sections`.
  - لا تغيير على سياسات RLS أو الصلاحيات؛ العزل بين المدارس يعمل حاليًا عبر `school_id` و`current_school_id()`.
- تحديث الإدخال في `src/routes/_authenticated/settings.tsx` (SectionsTab): حساب الرقم التالي من الشُعب الحالية للصف المختار داخل المدرسة النشطة، وحفظ `gender`.
- تحديث `src/hooks/useSectionGroups.ts` وقوائم الشُعب في `students`، `attendance`، `marks`، `homework`، `harvest`، `reports` لتحميل `gender` وعرضه في النص الموحّد للشعبة.
- إضافة دالة عرض مشتركة لاسم الشعبة (صف + رقم + النوع) واستخدامها في الصفحات وملفات PDF (`src/lib/print-pdf.ts` المستخدمة في التقارير) لتوحيد الشكل.
